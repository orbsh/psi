# 自动柯里化与偏应用

**状态**：候选
**一句话**：方法/函数是值，参数不足时自动降级成部分应用的函数值；`add 1` 是一个等待第二个参数的函数。

**动机**：高阶调用省一层块。`xs.map trim`、`xs.fold 0 add`、`let inc = add 1` 都成立，DSL 与组合子写起来短一截。这是 Haskell/OCaml 一侧的默认世界，很多算法写法（无点风、section、组合子）依赖它。

**形态**（若采用）：

```
let inc = add 1            # inc: Int -> Int
xs.map trim                # 不需要 {it.trim}
xs.map (add 1)
map2 (+) xs ys             # 运算符当值
```

**代价**：三处结构性开销。

1. **arity 饱和规则**：什么时候算「给满了」不再由声明唯一决定，链中段会产生半调用值，错误延后到下一条 step 才暴露。
2. **点的二义**：`x.f` 是取值还是调用？方法可值时两者同形，只能靠类型判定。
3. **链与函数的边界**：`a.x b.y` 里 `x` 若只吃到 `b`，`.y` 是作用在结果上还是喂给半调用？需要新规则。

如果在 ψ 里只要「省一层块」的收益，代价看起来不成比例——但这条判断本身可以改。

**冲突**：[16](16-methods-are-not-values.md) 正面冲突。[11](11-method-chain-primitive.md) 的「arity 决定消费几个步」是它的简化版：饱和一旦允许不足，那条规则就不再是错误检查而变成类型构造。

**若改掉会动到**：[11](11-method-chain-primitive.md)、[12](12-arity-grouping.md)（步数不再能静态核对）、[21](21-unified-dot-access.md)、[38](38-composition.md)、类型检查的收敛性（偏应用让推断更容易发散）。
