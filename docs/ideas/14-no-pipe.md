# 不设管道运算符

**状态**：在用（可改）
**一句话**：链本身就是管道——`x.f.g` 就是「先 f 后 g」的管道，不另设 `|>` 或 `▷`。

**动机**：管道符号和点访问是同义的记法，双记法只有负担：两种写法要选一种，格式化器要选一种，读代码的人要看到两种形态。方法链已经把「方向固定」这件事编码进语法位置（接收者在最左）。

**形态**：没有形态。`a |> {it.b}` 不存在，写 `a.b`。

**代价**：三步以上的链折成多行时，续行靠「下一行以 `.` 开头」这条规则识别，视觉上不如显式管道符整齐：

```
shapes
  .filter {s| s.area > 2.0}
  .map {it| Report.line it}
```

另外接管 nushell 风格的读者会找管道符；习惯 `|>` 的人第一次写会报错。

**冲突**：[15](15-pipe-operator.md) 主张要管道符。两条可以并存（同义双记法），也可以只留一条；这是记法之争，不动语义。
