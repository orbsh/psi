# 线性多遍，无不动点

**状态**：在用（可改）
**一句话**：目标不是「单遍」，是「线性多遍、无不动点、无优化管线」；编译时间落在编辑循环里（千行级脚本 ~10 ms 量级，随行数近线性）。

**动机**：「单遍」的字面意思是扫一遍源码就出机器码，那是 C 时代流式编译的遗产。它要求声明先于使用、不能跨声明推断、不能拿全程序信息决定派发。有类型推断就不可能真单遍：至少要先收签名再查体（文件内两遍），再按接收者类型解析 trait、插入字典（按需一次，不迭代）。真正决定编译时间的是「有没有不动点」，不是遍数。

**形态**：

| 阶段 | 做法 | 省掉的东西 |
|:--|:--|:--|
| 词法 | 单遍，仅识别负字面量与换行续行 | — |
| 语法 | 递归下降，步文法无歧义 | 优先级/结合性声明表、fixity resolution |
| 解析 | 局部槽拉平为数组，`self` 链尾递归 | 作用域树遍历 |
| 类型 | 双向检查，期望类型灌入块；种类只做 arity 校验 | 全局合一、rank-2 推断、种类推断、高阶合一 |
| 降级 | 一 `def` 一函数，闭包一 struct | 单态化、内联、装箱优化 |
| 发射 | 直接二进制编码 | LLVM、链接器 |

四条「再来一遍直到没变化」的路径都不走：推断迭代到收敛、trait 选择互相依赖、宏展开轮数不定、单态化实例枚举。

**代价**：

- **推断能力被这条约束住**：双向检查 + 期望类型灌入，推不出来就要显式标注（`let xs: List<Text> = ...`）。没有全局合一意味着某些局部能推出的东西推不出。
- **没有不动点 ⇒ 没有宏 ⇒ 没有全语言的常量折叠/特化**：这是 [27](27-macros.md) 被卡住的地方。
- **性能目标未验证**：10 ms 是设计目标（未实现），靠的是结构而非工程打磨。
