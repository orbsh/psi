# 实参不加括号，arity 分组

**状态**：候选
**一句话**：实参写成链上的步，一个 primary 一步，不加括号也不加逗号；给几个由声明的 arity 决定。

**动机**：括号是「另开一个表达式层级」的记号。如果实参本身就是 primary 步，括号就只在需要把一条完整表达式压成一个值时才出现，出现频率降到很低，视觉噪音跟着降。

现在的表面用括号加逗号（[75](75-rust-surface-syntax.md)），这条作为「省噪音」的候选留着：它换来的是链跨过实参继续（`xs.map f.filter p`），付出的是分组依赖别处的声明。

**形态**：

```
x.replace "a" "b"          # 不是 x.replace("a", "b")
xs.map {x| x * 2}          # 块直接站实参位
f (a + b) c                # 要传表达式才用括号
```

arity 写在声明里：`def clamp lo: Float hi: Float -> Float` 是 arity 2，调用必须给两个步。给不够是编译错误，不是偏应用；给多了，多出来的步作用在结果上。

**代价**：混合调用链变长时要数步数。`x.replace "a" "b".trim` 里 `.trim` 作用在结果上（因为 replace 已吃满），但眼睛看过去容易以为它在第三参位置。另外空白在 ψ 里有语义（`a b` 是一次调用），这限制了代码格式化器的自由度——不能像大多数语言那样随便折行。

**冲突**：[11](11-method-chain-primitive.md) 的记法就是这个；换成括号逗号（`f(a, b)`）保留同一个原语，但步进感消失，`xs.map f.filter p` 那类「链跨过实参继续」的写法要重写。与 [1A](1A-named-infix.md) 的字母名中缀直接冲突：空白应用占着那个位置。
