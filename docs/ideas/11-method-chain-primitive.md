# 调用只有一个原语：接收者 + 名字 + arity 个实参

**状态**：在用（可改）
**一句话**：整个语言的调用面压成一件事——一个接收者、一个方法名、声明规定数量的实参；管道、中缀、运算、模块都是这条的记法，不是另外的机制。

**动机**：展开目标只有一个，解析规则就能写成几条固定规则；每多一个展开目标（`+` 走一套、`for` 走一套、`map` 走一套），规则数量就随特性相乘。这也是与 Scala 的分界线：Scala 的核心语义同样是方法调用加多层糖，但每种糖各管一段。

**形态**：

```
x.trim                  // 零参调用
x.replace("a", "b")     // 两参调用：replace 的声明有两个参数
xs.map(|x| x * 2)       // 闭包是普通实参
```

```
chain     = primary ( '.' name ( '(' args? ')' )? | '(' args? ')' | '?' )*
```

三条解析规则：

- **每步作用于整条前缀**：`x.f(a)` 作用在 `x` 上，`.g` 作用在 `x.f(a)` 上。链的读法不变。
- **分组由括号给，不看 arity**：实参写在括号里，逗号分隔；arity 只决定「给几个才合法」，不再决定「谁吃谁」。所以读一个片段不需要知道别处的声明。
- **零参不写括号**：`x.f` 是零参（字段与零参方法是同一件事），`x.f(a)` 有实参。括号因此只表示「这次调用带实参」，表示式的信息量回到括号本身。

中缀最松，优先级取 Rust 的表，自定义符号按首字符挂档（[13](13-infix-by-spelling.md)）。

读法实例（左 → 唯一读法）：

- `x.f(a, b)` → 一次二元调用
- `x.f(a, b).g` → 先调 `f`，再在结果上读零参 `g`
- `xs.map(|x| x * 2).filter(|x| x.n)` → 链，实参不外溢
- `x.f()` → 编译错误：`f` 零参，括号里给了实参；反之 `x.g(a)` 少给也是错误
- `a + b * c` → `a + (b * c)`——Rust 的优先级表
- `a <+> b.c` → `a <+> (b.c)`——中缀两侧各是一条链
- `f(g(h(x)))` → 合法但不流畅：主语被埋进参数里（[76](76-fluency-over-terseness.md) 第 1 条）

**代价**：arity 仍在声明里（调用必须给满，多给少给都是编译错误），但分组不再依赖它，所以屏幕上读片段这件事不再需要外部信息——这是照 [75](75-rust-surface-syntax.md) 换表面换回来的。剩下的代价有两处：「零参不写括号」要教一遍（Rust 读者会以为 `c.area` 是字段）；`x.f` 与 `x.g(a)` 混排时，读者要靠「有没有实参」判断每一段是取属性还是调用。另外[12](12-arity-grouping.md) 那种「链跨过实参继续」的写法没了，实参括起来之后链只在括号外延续。

**冲突**：[12](12-arity-grouping.md) 说的是这个原语的记法（不带括号）；换记法（括号 + 逗号）会保留 `arity` 概念但改变分组规则。[13](13-infix-by-spelling.md) 是它的中缀记法。[14](14-no-pipe.md) 说管道就是这个原语，[15](15-pipe-operator.md) 说要另设符号。若 [16](16-methods-are-not-values.md) 反过来（方法成为值），这条原语要再加一套「名字在表达式里表示什么」的规则。
