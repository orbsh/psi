# 禁止跨层反向引用：只比深度

**状态**：候选
**一句话**：把「悬空指针」消成一条可静态检查的规则——指针所指区域必须活得不短于容器所在区域；每个区域的深度是个数字，赋值时比一次大小。

**动机**：Rust 的痛苦来自「任意网状引用 + 微观到单条语句的生存期」。如果只要求宏观层级，检查就从「解一组生命周期约束」退化成「比两个整数」。每个区域在创建时就确定深度：根区域 0，每进一层加一。合法赋值判据只有一条：

```
depth(被指向的区域) ≤ depth(容器所在的区域)
```

即：容器活得比目标短或一样长 → 允许；容器活得比目标长（深层指针塞进浅层变量）→ 编译错误。用户侧的说法是「深层的指针不能赋给浅层的变量」，同一个不等式。

## 为什么这在 B 形态下是线性的

- 深度是**静态的**：区域句柄的深度由语法位置决定（根/函数/块/子区域），调用时被调者的「caller」深度就是调用点所在区域的深度——不需要推断，也不需要统一。
- 检查是**逐边的**：每次 `container.field = ptr` 比一次；不需要分析整棵树，也不需要路径敏感的逃逸分析。
- 混合来源的树自动合法：树节点在新区域，但某个叶子指向更外层的 interned 字符串——`depth(interned) ≤ depth(node)`，通过；反过来（长命节点指向短命文本）被拒。**没有「整棵树要不要提升」这个问题，只有一条条边合不合法。**

## 边界与代价

- **它就是 Rust 的生命周期检查删掉精度**：同一个不等式族，但只有「区域」这一级，没有 `'a: 'b` 的传递闭包与协变/逆变。能用它表达的关系都是粗的——「这个值比那个活得长」，说不出「活到循环体结束」。
- **常见模式要挪代码**：函数返回一个引用参数的视图（`split`、`iter`、`borrow`）时，签名必须写「返回值属于哪个区域」；若那个区域是参数的，调用者必须保证参数活得够久——一条约束换回一次标注，比 Rust 少，但不是零。
- **错误信息要能说清深度**：「这个值在请求区域（深度 2）里，你要把它放进连接区域（深度 1）」是可解释的；这正是比 Rust 好讲的地方。
- **并发**：区域是线程局部的，跨线程共享数据必须进长命区域或 GC 堆，否则深度规则管不到数据竞争（它只管悬空）。
