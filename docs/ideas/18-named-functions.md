# 独立具名函数

**状态**：候选
**一句话**：允许 `func`/`fn` 形式的顶层函数，不挂在任何容器上——`f x y` 里 `f` 是自由函数名。

**动机**：算法天然没有接收者。`gcd a b`、`zip xs ys`、`parse text` 里那个「主语」是硬凑的；把 `gcd` 挂成 `Int.gcd` 或 `Math.gcd` 都是把分类问题伪装成所有权问题。自由函数也消除「这方法为什么在这个类型上」的争论。

**形态**（若采用）：

```
func gcd a: Int b: Int -> Int = ...

gcd 12 8            # 零接收者调用
xs.map {it.gcd 2}
```

**代价**：

- **零参调用没有记号**。名字表示值和表示调用同形（`f` 是函数还是它的结果？），要么全语言加一个记号（`f` 取函数、`f()` 调用），要么给零参函数开例外。
- **链的入口出现两个**。`x.f.g` 和 `f x y` 并存，读代码时要知道名字是哪一类。这对「一个原语」是实质削弱。
- **数据先行的杠杆失效**：散参数重新获得舒服的位置，`f a b c d e` 不再别扭。

反过来看，如果语言的重心是无点风与高阶组合，这条代价可能比它带来的自由更便宜。
