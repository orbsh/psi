# 寄存器式指令，批量操作码由编译期选

**状态**：候选

**一句话**：指令集是寄存器式；"把顺序无关的访存合成一条"由编译期在一张固定操作码表里选，不由运行时猜；运行时不做流上的自动向量化。

**动机**：解释器的成本结构是"每条指令一次分派"，分派是首要瓶颈（Ertl & Gregg）。因此降低指令条数的收益大于降低单条指令的成本——寄存器式指令相对栈式实测少执行约 47% 的指令、快 26% 到 32%（Shi et al., VEE'05；SPE 2025 复核）。批量操作码是同一思路的延伸：一段循环的访存合成一条指令，分派成本摊到 N 个元素上。

## 为什么不是"把 push/load 攒一批"

把栈上连续的 push/load/store 打包执行，等于在栈机上手工模拟寄存器机：还要多出打包与临时区的开销。直接做成寄存器式，同一个效果在指令集层面就成立——表达式整体编译成一条指令（`a[i] + b[i]` 是一条 `ADD_F64 r0, r1, r2`，不是六条 push/load）。

"把顺序无关的指令重排成一批"则是另一件事：它需要依赖分析与别名分析，是优化器。在值语义下别名消失、重排安全，但"哪几条能合"仍然是一次分析。可行的收窄形态是固定的批量操作码表，不做通用重排。

## 为什么 wasm 是栈式却快

wasm 快不是因为栈式，是因为执行时栈不存在。它是给编译器吃的传输格式：V8 走 Liftoff（基线）到 TurboFan（优化），Wasmtime 走 Winch 到 Cranelift，操作数栈在编译时被寄存器分配吃掉，产物是机器码。同一份 `.wasm` 交给解释器（wasmi、wasm3）就掉一个档位——格式没变，慢在解释。

栈式被选为传输格式，是因为它把成本推给消费者：生产端不用做寄存器分配（栈位置隐含）、代码紧凑、可单遍校验（类型栈）、控制流结构化。解释成本原封不动留给运行时。

所以这里的选择不是"栈还是寄存器"，是"这笔账谁付"。宿主有编译器，ψ 白拿；自建 VM，要么解释时付（指令多 47%、时间多 26% 到 32%），要么加载时付一次机械翻译。

翻译不需要寄存器分配器，因为栈深度就是槽号：第 k 个压栈值落在 slot k，出栈只是深度回退，槽自动复用。`a + b * c` 在栈式下是五条指令（load a、load b、load c、mul、add），在槽式下是两条（`mul t, b, c`、`add t2, a, t`）——差的是指令数，不是分析。每函数一次 O(n) 翻译，字节码体积涨约 25%。

于是磁盘上可以存紧凑的栈式编码、内存里跑槽式指令：传输格式与执行格式分开，同一份 IR 两个出口。

## 形态

- **寄存器式指令**：局部变量与中间值都是帧内槽号，操作数显式命名，栈只用于调用。
- **批量操作码是一张固定表**，编译期按形态选，不生成新组合：
  - `map_add_f64 base, n`：两个数组逐元素相加写进结果区
  - `sum_f64 base, n` / `sum_i64 base, n`
  - `copy_n base, n` / `fill_n base, n, val`
- **可向量化的前提由语言保证**，全部是编译期已知：值语义无别名（[63](63-value-semantics.md)）、无副作用、元素类型已知、长度在指令里。静态类型把这些前移，不需要运行期判断。
- **处理器用 SIMD 写**：每条批量码的实现用 `std::simd` 或 intrinsics 展开，一次处理 4 到 8 个元素。向量化发生在解释器的实现里，不在被解释的代码里。
- **链式融合不做**：`xs.map f.map g` 仍是两段循环。融合需要跨段的形状分析与新代码生成，那是优化器（与 [52](52-no-optimizer.md) 冲突）。批量码只认单段循环。

## 代价

- **批量码不可中断**：一条指令执行 N 个元素，按指令计的超时、配额、信号要按元素折算，抢占粒度变粗。对"不可信扩展"的配额记账是实打实的额外字段。
- **操作码字母表会长**：每加一项都是编译器与解释器两端同改，两端要同步发布；字母表本身成为版本兼容面。
- **收益集中在数值数组**：f32/f64、整数数组上 SIMD 有收益；指针、字符串、记录数组上退化成一次 `memcpy`，与普通循环持平。
- **它离优化器只有一步**：一旦开始"按上下文组合批量码"（比如把两段合成一段、把批量码按实际长度特化），就变成了 pass 管线。边界要守住：表是固定的，选择是一次查表，不生成代码。

**冲突**：[52](52-no-optimizer.md)（这是"按固定表选指令"，不是优化管线；边界见代价最后一条）、[63](63-value-semantics.md)（值语义是向量化合法性的前提）。与 [77](77-bytecode-vm.md) 是形态细节关系。

**若改掉会动到**：[77](77-bytecode-vm.md) 的指令集形态、[52](52-no-optimizer.md) 的边界论证、解释器与编译器的字节码版本号、[56e](56e-drop-under-arena.md)（批量码与清理链的交互：一段批量拷贝里若有可析构对象，登记链要逐元素走）。
