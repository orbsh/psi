# 所有糖展开到同一个目标

**状态**：在用（可改）
**一句话**：管道、中缀、运算符、链式调用、模块访问，全部展开成「接收者 + 名字 + arity 个实参的步进链」；只有一个展开目标。

**动机**：一个目标，解析规则就能写成四条；多个目标，规则只能随特性乘法增长。Scala 的核心语义同样是方法调用加多层糖，但 `x + y`、`xs map f`、`for` 各走各的展开（`Int.+`、隐式转换后的方法、`map`/`flatMap`/`withFilter`），每种糖各管一段，规则数按特性相乘。

**形态**：

| 写法 | 展开 |
|:--|:--|
| `x.trim` | 零参调用 |
| `x.replace "a" "b"` | 链上追加两个 primary 步 |
| `a + b` | `a.+ b` |
| `a <+> b` | `a.<+> b`（符号名方法） |
| `xs.map f.filter p` | 两次步进调用，链即管道 |

**代价**：语法层面几乎没有「专属语法」的位置——`for`、`if let`、模式守卫这类东西要么用方法表达（`xs.each`），要么作为新的展开目标引入（于是这条被削弱）。另外它对语法糖的表现力有上限：凡是不能还原成「接收者 + 名字 + arity 实参」的构造，都得当作例外逐条写规则。

**冲突**：[32](32-inheritance.md)（若成立，隐式转换与子类型派发会引入第二个展开目标）、[15](15-pipe-operator.md)（管道符如果独立成语法而不只是符号名方法，就多一个目标）。

**若改掉会动到**：[11](11-method-chain-primitive.md)、[57](57-linear-compile.md)（解析规则数量）。
