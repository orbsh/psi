# 单态化

**状态**：候选
**一句话**：每个泛型实例都生成一份专用代码，`Box<Int>` 与 `Box<Float>` 各自编译成独立的机器码。

**动机**：运行时间是很多语言的第一约束。单态化后泛型方法被当作具体类型编译，内联、常量传播、寄存器分配全部可用，组合子链（`xs.map f.filter p`）能编译成和手写循环一样的代码。Rust 与 C++ 的模板都建立在这上面。

**形态**（若采用）：编译期收集所有实例化点，为每个 `(F, 具体类型)` 生成一份代码，再看需要打包成 `dyn` 版本。

**代价**：

- **代码量随实例数乘积增长**：`map` 用在 5 个类型上就是 5 份；嵌套泛型（`Map<Text, List<Box<Int>>>`）指数级爆炸。
- **编译时间随实例数增长**，而且与调用点数量相关——不是「与行数近线性」的量。这与 [57](57-linear-compile.md) 的「编辑循环内编译」直接冲突。
- **二进制体积**：wasm 模块是单文件产物，体积直接落在加载时间上。
