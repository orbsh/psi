# 字典传递

**状态**：在用（可改）
**一句话**：每个泛型方法只编译一份，trait 实现通过 `(trait, 类型或构造子)` 字典查表；全程序可见且接收者类型静态已知时，直接消解成函数索引。

**动机**：编译时间第一约束，二进制体积第二，运行时间第三。单态化让体积和编译时间随泛型实例数相乘增长；字典传递让一个泛型方法永远只有一份代码。对脚本规模，实例数少、调用次数也不密集，间接调用的代价很小。

**形态**：泛型方法编译一份，实现表在编译期确定（全程序可见），调用点插入字典参数或消解成直接索引。

```
impl<T: Add> Add for Box<T> {
  def + other: Box<T> -> Box<T> = Box { item: self.item + other.item }
}
```

`Box<Int>.+` 与 `Box<Float>.+` 共用一份代码，`Add` 字典在调用点传入。

**代价**：

- **间接调用**：热路径上每次 `+` 都过一层字典，跨实例特化不存在（`Box<Int>` 的 `+` 和 `Box<Float>` 的 `+` 是同一段代码，无法针对类型优化）。
- **内联失效**：泛型小函数不能内联展开，组合子风格（`map`/`fold` 链）的常量传播全废。
- **调试与体积**：堆栈里出现的是泛型版本，本来靠单态化分开的上下文字消失。

如果运行时间成为第一约束（比如语言落到数值或图像运算场景），这笔账要倒过来算。
