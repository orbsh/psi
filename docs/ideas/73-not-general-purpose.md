# 不是通用语言

**状态**：在用（可改）
**一句话**：ψ 的目标不是通用语言，是同一份小产物落进三个宿主的脚本语言——宿主里嵌的那一段业务逻辑。

**动机**：定位决定取舍优先级。定成通用语言，就要和 Rust/Go 比生态与性能，编译器就不能没有优化器；定成嵌入式脚本，编译时间、产物标准性、规格大小才是要守的线，运行时间可以让。

**形态**（这条定位推出的几条线）：

- 产物标准（[51](51-standard-wasm.md)）、编译快（[57](57-linear-compile.md)）、规格小（[54](54-wasm-gc.md)）。
- 规模假设是千行级脚本，不是十万行程序（[58](58-whole-program.md)）。
- 性能优先级：编译时间 > 二进制体积 > 运行时间（[33](33-dict-passing.md)）。
- 没有 shell 身份，没有包版本求解，没有链接器。

**代价**：定位一旦认下，几类需求就永远排在后面——数值计算、长驻服务、大代码库、需要精细内存控制的场景。用户若拿它当通用语言用会不断撞墙，而语言侧不该为此加特性。

**冲突**：与每一条「表达力更强」的想法冲突——[34](34-monomorphization.md)、[36](36-kind-inference.md)、[64](64-borrow-checker.md)、[65](65-core-async.md)、[27](27-macros.md)。冲突不是错误的证据，只是取舍的落点；改定位，这些就都成立。判断这类取舍的框架是 [74](74-asymmetric-payoff.md)（砍掉的那层必须在每次操作上收费，才换得回来）。

**若改掉会动到**：整个优先级排序。
