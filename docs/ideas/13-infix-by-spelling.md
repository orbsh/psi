# 符号名即运算符，优先级由首字符定级

**状态**：在用（可改）
**一句话**：`+` 就是方法名，`a + b` 是 `a.+ b` 的记法；任何符号名都合法，于是自定义中缀不需要任何声明动作，位置由首字符决定。

**动机**：运算符不是语法类别，只是名字的拼写类别。把定级规则钉在词法层，解析器就只看 lexeme，不看声明、不读导入——fixity resolution 这个阶段整个不存在，这是解析自足的关键。OCaml 用同一手法。

**形态**：

```
impl Vec { fn <+>(self, other: Vec) -> Vec { ... } }   // 定义后立刻可用
a <+> b                                               // 与 a.<+>(b) 完全等价
```

| 档 | 运算符 | 结合 |
|:--|:--|:--|
| 8 | `*` `/` `%` | 左 |
| 7 | `+` `-` | 左 |
| 6 | `<<` `>>` | 左 |
| 5 | `&` | 左 |
| 4 | `^` | 左 |
| 3 | `\|` | 左 |
| 2 | `==` `!=` `<` `<=` `>` `>=` | 不可连写 |
| 1 | `&&` | 左 |
| 0 | `\|\|` | 左 |
| −1 | 其余符号（如 `@@`、`▷`、`<+>`） | 左 |

这张表就是 Rust 的表，另加最后一档给自定义符号。首字符落在表上的符号直接认领该档：`<+>` 在比较级，`+>>` 在加减级，`**` 在乘除级。首字符不在表上的（`@`、`▷`）落到最低一档，比 `||` 还松。

**代价**：位置由拼写而不是语义决定。写 DSL 时要先决定「我这级放哪」，`+>>` 落在加减级、`<*>` 落在比较级（因此不能连写）——名字的美观被优先级绑架。九档加一档兜底仍可能不够用：两个自定义符号挤在同一档时，只能靠括号表态。

**冲突**：[1A](1A-named-infix.md) 是三种替代（字母名中缀、反引号、声明式 fixity）。与 [12](12-arity-grouping.md) 的空白应用直接冲突于「字母名能不能进中缀位」。档位够不够用是开放的；改造方向见 [75](75-rust-surface-syntax.md)（优先级表取 Rust 的）与 [76](76-fluency-over-terseness.md)（判据）。
