# 符号名即运算符，优先级由首字符定级

**状态**：在用（可改）
**一句话**：`+` 就是方法名，`a + b` 是 `a.+ b` 的记法；任何符号名都合法，于是自定义中缀不需要任何声明动作，位置由首字符决定。

**动机**：运算符不是语法类别，只是名字的拼写类别。把定级规则钉在词法层，解析器就只看 lexeme，不看声明、不读导入——fixity resolution 这个阶段整个不存在，这是解析自足的关键。OCaml 用同一手法。

**形态**：

```
def <+>  other: Vec -> Vec = ...   # 定义后立刻可用
a <+> b                            # 与 a.<+> b 完全等价
```

| 首字符 | 结合 | 例子 |
|:--|:--|:--|
| `*` `/` `%` | 左 | `a * b % c` |
| `+` `-` | 左 | `a + b - c` |
| `=` `<` `>` `!` | 不可连写 | `a < b`；`a < b < c` 不行 |
| `&` | 左 | `a && b` |
| `\|` | 左 | `a \|\| b` |
| 其余符号 | 左 | `a >>= b`、`a @@ b`、`a ▷ b` |

**代价**：位置由拼写而不是语义决定。写 DSL 时要先决定「我这级放哪」，`+>>` 落在加减级、`<*>` 落在比较级（因此不能连写）——名字的美观被优先级绑架。另外六个级别可能不够细。

**冲突**：[1A](1A-named-infix.md) 是三种替代（字母名中缀、反引号、声明式 fixity）。与 [12](12-arity-grouping.md) 的空白应用直接冲突于「字母名能不能进中缀位」。六级够不够在 [语法总表](../reference/syntax.md) 里是开放的。
