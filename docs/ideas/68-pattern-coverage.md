# 模式覆盖

**状态**：未定
**一句话**：`match` 目前只支持字面量、变体绑定与 `_`；记录模式与数组模式是否进 v1，没定。

**动机**：`match` 的威力在结构化解构。没有记录模式，从 `Json.Obj` 或嵌套 struct 里取值要先绑定变量再一次次访问；有了记录模式，`{ name: n, age: a }` 一次拿两个字段。

**形态**（候选）：

```
# 现在能做
match shape {
  Shape.Circle r -> r
  Shape.Rect w h -> w * h
  _ -> 0.0
}

# 记录模式
match user { {name: n, age: a} -> ... }

# 数组模式
match xs { [first, ...rest] -> ... }
```

**代价**：

- **记录模式要决定「部分匹配」语义**：只写两个字段能不能匹配一个有五个字段的记录？省略的字段是通配还是错误？
- **数组模式**要可变长（`...rest`），核心数组定长（[63](63-value-semantics.md)），两个概念打架。
- **穷尽性**：记录模式天然不穷尽（字段集合开放），要么放弃穷尽检查，要么给记录一个封闭字段假设。

**冲突**：[31](31-tags-not-trees.md)（穷尽是它的杠杆之一）、[63](63-value-semantics.md)（定长数组）。

**若改掉会动到**：`match` 的检查、[41](41-json-boundary.md)（Json 解构的写法）。
