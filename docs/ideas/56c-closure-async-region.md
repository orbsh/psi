# 闭包与 async：move 或独立区域树

**状态**：候选
**一句话**：闭包/异步任务若要捕获外层局部变量，必须 move（深拷贝）到自己的区域，或整棵树拥有独立的区域根；不允许捕获一个比自己活得短的区域的指针。

**动机**：「人走了，魂还在」是区域模型唯一处理不了的方向——帧退出了，任务还在读数据。用一条规则把它切断：**捕获 = 把数据搬进任务自己的区域树**，于是任务的存活与栈层级彻底解耦。

## 形态

```
# 方案 A：move 捕获，拷进任务自己的区域
spawn {|r| use x}            # x 深拷贝进任务区域根

# 方案 B：只许通过通道传独立所有权的数据
let ch = Channel.new()
spawn {|r| ch.recv}          # 任务不引用任何外层局部

# 方案 C：借用但把区域一起绑住（structured concurrency）
scope {|s| s.spawn {|r| use x} }   # 任务保证在 scope 内结束
```

- **A** 最省心，代价是全拷贝：每请求处理大 buffer 的网关要为每个任务复制一份。
- **B** 最干净，代价是表达力：想并行读同一份只读数据就得复制或走共享只读区域。
- **C** 是「借用 + 结构并发」的组合：任务生命期被 scope 限定，于是它可以借用 scope 区域的指针而不违背深度规则。**这条是 A 的代价和 B 的表达力之间的真实中点**，值得单独评估。

## 代价

- **A 的拷贝成本落在数据量最大的地方**（请求体、帧缓冲），而这正是区域模型想省的地方。
- **B 把所有跨任务交互推成消息传递**，与「共享只读大对象」的常见形态冲突。
- **C 需要编译器理解「任务不会比 scope 活得长」**，这是深度规则的自然延伸（scope 区域 = 一层），但要一套结构化并发的运行时支撑：任务必须在退出前 join，否则就回到 A。
- **异步 + 区域**还有一条隐藏规则：await 点恢复后，原来的栈帧没了，所以任务的状态机必须整体住在自己的区域里——状态机的大小与捕获集合必须可静态确定（`async` 的「不透明 Future」在这儿是个成本）。
