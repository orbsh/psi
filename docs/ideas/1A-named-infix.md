# 字母名中缀 / 反引号 / 声明式 fixity

**状态**：候选（三种做法，可各取其一）
**一句话**：让中缀不限于符号名——字母名也能进中缀位（`a gcd b`），或者用反引号（`` a `gcd` b ``），或者由声明指定优先级。

**动机**：符号名中缀把「哪些运算符存在」交给拼写，代价是可读性：`a >>= b` 好，`a ▷ b` 好，但 `a `<+>` b` 就难读了。字母名中缀让 DSL 用自然语言写：`user has role "admin"`、`x between 1 10`。

**形态**：三种做法并列，各自的形态与账写在下面三节里（不择一，可各取所需或都开）。

**代价**：见每种做法下的「代价」。

## 三种做法与各自的账

**字母名中缀**（`a y b`）：

- 收益：可读性最好；DSL 不需要符号词汇表。
- 代价：与空白应用正面冲突（`a b` 是调用），只能靠额外分隔符共存，或者砍掉值的应用语法改成 `f.apply x`。前者是第二种记法，后者把最常用的高阶写法推成链尾方法。

**反引号中缀**（`` a `y` b ``）：

- 收益：能消歧，词法上干净，Haskell 用了三十年。
- 代价：为一个糖引入一种 token 和一套错误信息；与「文法一页写完」冲突。

**声明式 fixity**（`infixl 6 +`）：

- 收益：优先级按语义定，不受拼写绑架；DSL 能自己决定层级。
- 代价：解析器必须读跨模块声明，解析与加载耦合，线性编译破产——这条在 [57](57-linear-compile.md) 的框架里是硬伤，但如果放弃「无不动点」也可以接受。

**冲突**：[13](13-infix-by-spelling.md) 是这三条的替代。[12](12-arity-grouping.md) 与字母名中缀直接冲突。
