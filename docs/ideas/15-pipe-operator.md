# 管道运算符

**状态**：候选
**一句话**：给一个显式的管道符号（`|>` 或 `▷`），让数据流的方向在每行开头可见。

**动机**：多步变换折行时，`.method` 开头的续行看起来像悬挂的分号，读者要靠缩进和规则推断这是同一条链。显式管道符让每一行自证：「左边的东西喂给右边」。

**形态**（若采用）：

```
shapes
  ▷ filter {s| s.area > 2.0}
  ▷ map {it| Report.line it}
  ▷ each {it| Io.stdout.println it}
```

按 [13](13-infix-by-spelling.md) 的规则，`▷` 是首字落在最低级的符号名方法，所以 `a + b ▷ {x| x}` 读作 `(a + b) ▷ {x| x}`——不需要为它单开语法。

**代价**：与 [14](14-no-pipe.md) 的冲突就是它自身最大的代价——同一个语义两种写法。如果要让它成为唯一写法，链的点访问就要退回「一步步」的形态，`xs.map f.filter p` 这种跨实参的流畅链会消失。另一个代价是它和美式 `▷`/`|>` 的视觉密度：一行一个符号，五行就是五个符号。

**冲突**：[14](14-no-pipe.md)。语义上不冲突，记法上互斥。

**若改掉会动到**：只需加一条记法；但若要独占，[11](11-method-chain-primitive.md) 的解析规则和 [12](12-arity-grouping.md) 都要重写。
