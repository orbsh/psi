# 非对称收益：砍能力面，换每次操作

**状态**：在用（可改）
**一句话**：主动放弃一批能力，条件只有一个——被放弃的那层能力本来要在运行时、在每次操作上收费。砍掉它，让损失由作者一次性付清，收益由每次操作兑现。

**动机**：这是 ψ 与 OKM 共用的同一条设计原则。它不是「少做点东西」，是成本的形状不同：

- **损失一次付**：作者在声明时、编译器在编译时付。少了规划器、少了优化器、少了运行时解释层。
- **收益每次收**：每一个键、每一次解码、每一次调用都兑现。

反过来，如果被砍掉的能力只是一次性开销（比如「要写更多样板」），那砍它就不划算——省下的是一次性的，损失是每次的。

## 三个例子

**ψ**：没有宏（[27](27-macros.md)）、没有种类推断（[36](36-kind-inference.md)）、没有单态化（[34](34-monomorphization.md)）、没有优化器（[52](52-no-optimizer.md)）——每一条都砍掉一个「随程序数据相关增长」的机制，换编译时间与规格大小这两个每次保存都兑现的东西。

**区域模型**（[56](56-hierarchical-arena.md) 系列）：禁止跨层反向引用（[56b](56b-depth-check.md)）砍掉「任何引用都能互相指」的自由，换每次分配与释放都是 O(1)；代价是作者要在签名上写区域约束——一次付清。

**OKM**：没有查询语言、没有优化器、不能即席查询、部分模式不支持；换键是指针偏移、解码是切片、一次语义写入一次提交、引擎选择免费。同一条原则写在 `~/world/okm/README.md` 的「The bet」一节。

## 代价

- **限制必须是可静态检查的**：否则它退回运行时，收益消失只剩损失。「不能跨层反向引用」能检查（比深度），「不要写太长的函数」不能。
- **缺席的能力不会自动回来**：即席查询、宏、类型推断这类东西，用户会反复要；拒绝的立场要能一直撑住，否则半途加回来就是把两边的账都付了。
- **非对称的判断会过期**：如果某个被砍的机制变得足够便宜（编译速度快一个量级、宿主提供了它），这笔交易要重算。这条文档的存在就是为了方便重算，而不是为了守住结论。

**冲突**：所有「加能力」的想法——[27](27-macros.md)、[34](34-monomorphization.md)、[36](36-kind-inference.md)、[64](64-borrow-checker.md)、[65](65-core-async.md)。冲突不等于谁错：它们各自要在这条框架下算一次「一次付 vs 每次收」。

**若改掉会动到**：[73](73-not-general-purpose.md) 的定位论证、每一条「不加某能力」的文档的取舍方向。
