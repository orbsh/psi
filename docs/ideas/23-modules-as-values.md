# 模块是值，import 是绑定

**状态**：在用（可改）
**一句话**：`let Shapes = import "./shapes.psi"`；import 返回被导入文件的模块对象，类型位置上的 `Shapes.Circle` 是这个对象上的类型投影。命名空间不是树，是对象链。

**动机**：只有一种「名字从哪来」的机制。文件路径仍然是树，但那只是寻址工具；名字解析不依赖树，也就不需要第二套复用拓扑。名字是第一类值，可以传递、可以参数化。

**形态**：

```
let Shapes = import "./shapes.psi"

def render c: Shapes.Circle -> Text = ...
```

名字解析顺序：局部槽 → 当前容器的 `self` 方法 → 外层容器。循环 import 是编译错误（或两阶段初始化，见开放项）。

**代价**：import 是表达式，所以它出现在语句位置，模块的拓扑不再从文件头一眼可见（要看全局搜索 `import` 才知道依赖图）。另外模块对象可被赋给变量并传递，等于允许把依赖注入做得比大多数语言都隐式——`Config` 是模块还是配置实例，读代码时不好分。类型位置上的 `Shapes.Circle` 依赖值 `Shapes`，值与类型两层混在一处，这在实现上是把类型当成模块对象的成员。

**冲突**：[24](24-namespace-tree.md) 是同话题的另一种做法。[18](18-named-functions.md) 会让 import 变成「把名字带进当前作用域」而不是绑定一个值。
