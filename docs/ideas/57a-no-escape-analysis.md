# 没有逃逸分析：分配点与逃逸点都在语法里

**状态**：在用（可改）
**一句话**：ψ 不需要逃逸分析——值不可变、没有引用，「指针离开作用域」这个问题不存在；要接区域（[56](56-hierarchical-arena.md)）之后需要的也不是分析，是逐点决定。

**动机**：逃逸分析存在的理由是「对象的地址可能离开作用域」，编译器据此决定放栈还是放堆、要不要同步。没有地址概念时，它服务的问题不成立：ψ 里没有 `&`、没有 `*`、没有引用类型，闭包按值捕获，跨边界只有字节（[62](62-byte-boundary.md)）。谁都不指向谁，就没有「谁逃出去了」要判定。

## 线性、无不动点的真正来源（三条，都不是方法链）

- **没有引用**：没有指向图要解。区域推导难，难在子集约束要在调用图上传播；没有引用，约束就只写在签名上。
- **分配点局部、逃逸点可枚举**：构造只发生在 struct 字面量、list 字面量、text 插值这些语法位置上；逃逸只有三类——返回值、写入 root/global、被 spawn 捕获。两个集合都在语法里，所以每个逃逸点是一次**局部决定**（这次构造落 caller 区域还是当前区域），不需要跨调用传播。
- **值不可变**：没有 move、没有 borrow、没有所有权转移的状态机。区域不需要跟踪「这块内存现在归谁」。

方法链省的是**解析规则数**（[59](59-single-expansion-target.md)）：一个展开目标，四条解析规则。它不省逃逸分析——那件事由「无引用 + 值语义」解决，与记法无关。位置说反了会让后续判断全错：换成 Rust 皮（[75](75-rust-surface-syntax.md)）之后，前三条一条都不变。

## 与 Tofte–Talpin 的分界

那套（MLKit）推断的是**区域变量**之间的子集约束，逃逸结论沿调用图传播到收敛——那是不动点，也是它贵的根源。这里区域是**参数**（[56a](56a-region-param-passing.md)）：约束写在签名上（`-> caller.X`），检查一次即可。差别不在算法快慢，在「区域归属是推断出来的还是给出来的」。

## 代价

- **「只有三类逃逸点」是个强前提**，不是自然事实。任何新语法形态都可能加第四类：generator、协程、可变的宿主句柄图、宏生成声明（[27](27-macros.md)）。每加一类，就要重新论证它仍可局部判定。
- **省掉的精度换成了默认**：没有推断意味着推不出来就用默认（当前区域 / root 区域）。局部视图类 API（返回参数的一部分）写不出来，除非签名显式写区域约束。
- **它只对「没有引用」成立**：一旦引入引用（[64](64-borrow-checker.md)），逃逸点立刻从三类爆炸成任意赋值，回到约束求解。

**冲突**：[64](64-borrow-checker.md)（引用让这套失效）、[27](27-macros.md)（宏加逃逸点）、[65](65-core-async.md)（状态机是新的分配与逃逸点）。
