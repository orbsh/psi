# 没有优化器，没有 LLVM

**状态**：在用（可改）
**一句话**：后端是「类型化 HIR → wasm 指令序列」的线性化，不做 SSA、不做指令选择、不做寄存器分配、不做循环变换。

**动机**：wasm 是显式栈机——表达式按后序发射，操作数落在栈上，局部变量是索引化 slot。LLVM 的主要价值在优化，不在「能不能生成机器码」；wasm 目标下这一整层与目标机耦合的机制直接不存在。省掉的不是优化质量，是机制。

**形态**：一 `def` 一函数，闭包一 struct，直接二进制编码，无链接器。

**代价**：

- **代码质量全靠前端的形态**：少一层优化，链式代码会有多余的中间分配，`xs.map f.map g` 生成两趟遍历而不是融合成一趟。
- **二进制体积**：不做 DCE/内联，未用代码留在模块里（可以用简单的可达性分析补，但那是第二个优化器）。
- **没有优化器 = 没有可预测的性能模型调整空间**：想提高热点性能只能改语言或调度宿主。
