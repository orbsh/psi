# 装饰器是编译期标签

**状态**：在用（可改）
**一句话**：`@名字` 或 `@名字(实参)` 写在被装饰声明的前一行，不生成代码——它改的是编译器怎么处理这条声明，不是把声明包成另一个值。

**动机**：语言的形状决定了包装没有落点。Python 的装饰器等价于 `f = deco(f)`，前提是方法能当值；ψ 里方法不是值，也没有宏，所以「把一段行为包进另一段行为」无处安放。剩下合法的能力只有一条：把意图写进声明，让编译器执行。

**形态**：

```
@export("parse")
@deprecated("用 Csv.parse 代替")
def parse line: Text -> Row = ...
```

v1 语汇（编译器定义，不能用户扩展）：

- `@export` / `@export("name")`：导出成 wasm export；`main` 仍是默认约定。
- `@test`：测试入口，`psi test` 收集，不参与正常导出。
- `@deprecated("理由")`：调用点告警，仍可编译。
- `@target("browser" | "cli" | "host")`：只在对应宿主编译时存在；其他宿主引用即编译错误。三宿主的差异走这条，不走运行时分支。

**代价**：语汇固定，不能当库的扩展点。`@cached`、`@retry`、`@route` 这类想当然的装饰器都写不了；想要的包装只能靠显式写代码或用别的手段（入口表、手写包装类型）。这是把库的表达力换成了编译时间的可预测性。

**冲突**：[26](26-python-decorators.md) 是另一种做法（要方法可值），[27](27-macros.md) 是另一种（要宏）。这条本身就是 [16](16-methods-are-not-values.md) 的推论。
