# 装饰器是编译期标签

**状态**：在用（可改）
**一句话**：`@名字` 或 `@名字("实参")` 写在被装饰声明前；内建的那几条不生成代码——它改的是编译器怎么处理这条声明，不是把声明包成另一个值。表外的名字落到用户宏，那是另一层（[27](27-macros.md)）。

**动机**：语言的形状决定了包装没有落点。Python 的装饰器等价于 `f = deco(f)`，前提是方法能当值；ψ 里方法不是值，值层没有落点（语法层的宏是另一件事，见 [27](27-macros.md)）。剩下合法的能力只有一条：把意图写进声明，让编译器执行。

**形态**：

```
@export("parse")
@deprecated("用 Csv 代替")
fn parse(line: Text) -> Row { ... }
```

v1 语汇（编译器定义，不能用户扩展）：

- `@export` / `@export("name")`：导出成 wasm export；`main` 仍是默认约定。
- `@test`：测试入口，`psi test` 收集，不参与正常导出。
- `@deprecated("理由")`：调用点告警，仍可编译。
- `@target("browser" | "cli" | "host")`：只在对应宿主编译时存在；其他宿主引用即编译错误。三宿主的差异走这条，不走运行时分支。

表外的名字归用户宏（[27](27-macros.md)）：内建优先，同名冲突是编译错误。四条内建的共同点是「编译器知道它」——用户宏写出来的标签，编译器并不认识。

**代价**：内建语汇固定，不能自己加。表外的名字能落到用户宏（[27](27-macros.md)），所以 `@cached`、`@route` 这类东西由库提供——形状一样，来源不同：内建的编译器认识，宏写的编译器不认识。读的人要先分清手里这个是哪一层。这是把编译器能力与库能力分开，代价由读的人付。

**冲突**：[26](26-python-decorators.md) 是另一种做法（要方法可值），[27](27-macros.md) 是另一种（要宏）。这条本身就是 [16](16-methods-are-not-values.md) 的推论。
