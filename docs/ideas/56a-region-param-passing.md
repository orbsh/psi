# 区域当参数：把「提升」变成选句柄

**状态**：候选
**一句话**：区域不是推断出来的对象，是一个可以像参数一样传的**值**；函数签名写区域约束（`-> caller.Obj`），编译器把它编译成一个隐式实参，被调者的一切分配都落在那块区域里。

**动机**：MLKit 的「层级提升」是一次编译期改写——要判定哪些对象逃逸出内层，才能把它们搬到外层。改写是难的部分，因为它要跨调用图传播结论。如果区域是**传进来的句柄**，这件事根本不需要判定：被调者分配到哪里，是调用者在入口就给定的。于是「提升」不再是一次变形，而是一次选择。

这条正是把 [56](56-hierarchical-arena.md) 的形态 A 换成形态 B 的那一步，也是这套设计里最关键的一步——它把 [57](57-linear-compile.md) 的「不动点」反对整个消掉。

## 形态

```
def parse text: Text -> caller.Json = ...        # 整棵树的落点：调用者的区域

# 编译成
def parse text: Text r: Region -> Json
```

递归下降的每一步都透传同一个句柄（编译器插的，不是程序员写的）：

```
def value t: Text i: Int r: Region -> (Json, Int)
```

于是「返回一棵深度嵌套的树」不需要任何提升动作：**树的 N 个节点是同一个句柄的 N 次 bump 分配**。树是深的还是浅的、有几个分支，与区域无关——区域不是形状。

## 什么时候需要多块区域

- **输入与输出要同区域或更外**：若解析结果零拷贝指向源文本（字符串切片），签名得多一条约束 `region(text) ⊒ caller`——即调用者必须已经把文本握在手里。这就是「一个请求一个区域」的由来：源文本、解析树、响应字节全在同一区域，谁都不比谁活得长。
- **要把子树挂到另一块区域**：合法但不免费——跨区域挂载就是复制（把子树搬进目标区域）。允许显式写 `tree.move_to r`，让这笔拷贝出现在代码里，而不是隐藏的推断结果里。
- **失败路径**：中途失败时已分配的节点留在目标区域里，直到区域结束。长驻循环里反复解析时，把每次解析放进目标的子区域，成功后再决定是否整块搬出去。

## 代价

- **ABI 变化**：每个带区域约束的函数都多一个隐式参数，跨宿主边界要定义句柄的编码（一个基址 + 一个上限）。
- **签名开始承载效应**：`-> caller.X` 是函数类型的一部分，高阶传递时要一路带着；`Fn` 类型得能表达「在谁的区域里分配」，否则高阶函数的区域信息丢失，只能保守地要求全局区域。
- **调用者必须先有区域**：模块顶层初始化、`main` 之前的东西没有调用者区域，需要一个根区域（进程级），而它退出时才释放。
