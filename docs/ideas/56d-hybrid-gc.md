# 小 GC 兜底：两套堆，零互指

**状态**：候选
**一句话**：区域管批量死亡的数据，一个小的追踪式 GC 管跨区域共享与长寿命的少数数据；两套堆之间不互相持有指针，跨界只走显式句柄或复制。

**动机**：纯区域模型在「对象独立生死」的场景里没有表达力（缓存、索引、场景图、跨请求共享的会话）。承认这一点、留一个小 GC，比把区域推到所有地方更诚实。分区之后，GC 只需扫一小块内存，停顿与碎片都被限住。

## 形态

```
Region 堆（linear memory，bump）        GC 堆（宿主托管）
  请求级树、解析结果、batch buffer         会话表、缓存、跨请求共享对象
  整块释放                                可达性回收
```

## 规则（这条不写清就不成立）

- **区域 → GC 允许**（区域对象持有一个 GC 对象的引用，只要那个对象确实活着）。
- **GC → 区域禁止**（GC 对象不能指向区域里的东西，否则 GC 追踪到已擦除的区域）。
- **wasm 上还要更严**：wasm-gc 的追踪器看不见线性内存里的指针。所以「区域 → GC」在 wasm 上也必须通过**根注册**（把 GC 引用登记到 GC 可见的根表）才能成立；否则对象可能在区域还活着时被收掉。最省事的落地是：**两套堆之间零指针，跨界一律走「按值复制」或「显式句柄表」**。

## 代价

- **跨界成本**：把区域里算好的数据交给 GC 堆（或反过来）是复制或句柄查表；每次序列化/缓存写入都付。
- **两套分配规则要教给使用者**：什么时候该 `region.New`、什么时候该 `gc.New`，一旦选错就要复制。这是 Go 与 Rust 都没有的心智负担，也是这套设计最容易「体验像 Go」不成立的地方。
- **逃逸判定的边界其实没消失**：对象可能在运行中被「升级」到 GC 堆（比如被缓存），而升级 = 复制，或要求它的整个区域活得够久——后者会把区域寿命拉长到全局，区域就退化成 GC。
- **GC 的实现负担回来了**：哪怕很小，也要写分配器、写屏障（若区域对象被 GC 引用则不需要，反之要）、精确根扫描。
