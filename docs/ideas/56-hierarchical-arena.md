# 层级 arena 与区域回收

**状态**：候选
**一句话**：把栈的 LIFO 层级映射到堆——进一个函数/块就开一块区域，内部 bump 分配，退出时整块擦除；分配与回收都是 O(1)，区域内部无碎片。

**动机**：这是「追踪式回收」之外唯一在工业界站得住的替代（MLKit 是完整先例）。回收时机绑定到作用域，尾延迟可预测：没有 GC 停顿，只有整块释放；热路径上分配退化成一次指针加法。

## 两种形态，账完全不同

**A 推断式**（Tofte–Talpin，MLKit）：每个分配点带一个区域变量，逃逸结论沿调用图传播到收敛；「层级提升」（elevation）是一次编译期改写——把逃逸出内层的对象搬到外层区域。

- 收益：程序员零标注。
- 代价：全程序约束求解到收敛，正是 [57](57-linear-compile.md) 说的「不动点」；改一行可能改一片结论。

**B 参数式**（显式/隐式传 region handle）：区域不当推断对象，当一个**值**——调用时把「在哪块区域分配」作为隐式参数传下去，函数签名上写区域约束，而不是让编译器去猜。

- 收益：检查变成一次遍历，不动点消失；提升不再是改写，而是「入口选对句柄」，见 [56a](56a-region-param-passing.md)。
- 代价：区域语义进入调用约定（ABI 多带一个参数），跨宿主边界要定「谁开谁关」。

这条想法能不能成立，几乎完全取决于选 A 还是选 B。下面三项难点按 B 写。

## 三项难点（按 B 形态）

- **长尾膨胀**：外层区域被内层长时间占住——一个大对象挂在外层，此后内层所有分配都堆在它后面，直到外层退出。A 靠区域近似解释，B 靠句柄选择避免（把大对象放进单独的子区域）。
- **跨层反向引用**：内层把指针写进外层或全局，帧退出后悬空。B 下这是**唯一需要检查的东西**，方法是比深度，见 [56b](56b-depth-check.md)。
- **闭包与异步任务活得比帧长**：所有权转移或独立区域树，见 [56c](56c-closure-async-region.md)。

## 与 GC 的混合

现实形态通常是「区域管 90%，小 GC 兜底跨区域共享」，两套堆之间的指针规则必须是一条硬线，见 [56d](56d-hybrid-gc.md)。ψ 里另一条更省的路是**宿主侧的请求级 arena**：宿主在一次调用或一个请求的入口开区域、结束时整块释放（Go 的 arena 实验、Web 服务器的连接级池都是这一层），对语言完全透明，因为跨边界本来就只传字节——省掉的是语言内建那一整套 [56a](56a-region-param-passing.md)/[56b](56b-depth-check.md)。

## 代价（不分形态的部分）

- **分配器所有权**：要求语言自己拥有分配器与对象布局，与 [55](55-own-gc.md) 是同一条代价换名字——`region` 就是「编译器替你管的 arena」。
- **回收粒度就是区域**：想单独回收一个对象不行，错误路径上的垃圾要等到区域结束（请求级可接受，长驻循环里要开子区域）。
- **峰值内存放大**：整块释放意味着峰值是同时活着的最高层区域的累加，不是活跃对象之和。
- **动态派发要保守**：`dyn Trait` 的值可能来自任意区域，要么强制放进长命区域，要么禁止它跨区域持有数据。这会推着 [33](33-dict-passing.md) 的选择往 [34](34-monomorphization.md) 靠。

**冲突**：[54](54-wasm-gc.md)（区域模型要自建 linear-memory 堆，与「内存下沉给宿主」互斥）、[55](55-own-gc.md)（同一件事换名字）、[57](57-linear-compile.md)（只与形态 A 冲突；形态 B 消解它）、[63](63-value-semantics.md)（不可变值让原地更新不成立，区域收益集中在树/流的批量构造）、[64](64-borrow-checker.md)（区域给粗粒度长寿，借用检查给细粒度）。
