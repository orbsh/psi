# 宏与编译期求值

**状态**：候选
**一句话**：允许程序在编译期生成声明或代码，把语言的扩展权下放给库。

**动机**：装饰器只解决「在声明上打标签」，宏解决「生成新声明」——派生序列化、生成测试、内联 DSL、编译期常量折叠。没有宏，语言的一等扩展能力就停在编译器作者手里，库只能提供运行时抽象（而运行时抽象又要付性能与 arity 的代价）。

**形态**（两种可选载体）：

- **声明级宏**：输入是一份声明清单，输出是声明清单；单轮展开，不迭代。
- **wasm 载体宏**：编译器已经内嵌 wasm 运行时，宏本身可以是 wasm 模块——语言自举，不需要第二套宿主语言。

**代价**（这是最贵的一条想法）：

- **展开轮数不定、能生成声明**，编译时间从「与代码行数近线性」变成「数据相关」，直接冲掉 [57](57-linear-compile.md) 的地基。
- **语法对象化**：宏要吃语法树，就得把语法树变成语言里的一等对象，语言里出现第二层「表示代码的值」，同像性要求随之而来（[71](71-kdl-surface-syntax.md) 里对 KDL 的批评同源）。
- **消费表达式需要 arity**：宏若要看调用点的表达式，就得知道调用点的 arity，而那是刚收完的签名表——等于让宏把类型信息当地基，编译顺序锁死。

折中版本：宏只许生成**声明**、单轮展开、输入是声明清单而不是任意语法树，那么「不动点」这条可以保住，代价是宏写不出内联 DSL。声明清单的文本表示可以用 KDL（节点 + 位置实参 + 子块，与声明层同形），但它只是外部表示，不进表达式语法。

**冲突**：[25](25-decorators-as-tags.md)（固定语汇 vs 可扩展）、[57](57-linear-compile.md)、[59](59-single-expansion-target.md)。

**若改掉会动到**：[25](25-decorators-as-tags.md) 的语汇表、[57](57-linear-compile.md) 的「无不动点」、解析器（要能接受展开后的声明）。
