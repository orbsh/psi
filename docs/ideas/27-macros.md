# 宏是语法层的函数

**状态**：在用（可改）

**一句话**：宏是编译期执行的普通函数，输入输出是 token 流；写法照 Python 装饰器——`@name` 或 `@name(实参)` 挂在其后的声明上，在类型检查之前跑，看不到类型。

**动机**：装饰器的语汇固定在编译器作者手里（[25](25-decorators-as-tags.md)），库要生成序列化、测试入口、路由表这类声明就只能靠宏。机制照 Rust 过程宏：吃 token，不吃带类型的语法树，因此不把类型检查拖进第二遍。记法照 Python 装饰器：一个 `@`，挂在声明前，没有第二套括号语法。

**形态**：

- **只有一种位置**：`@name` 或 `@name(实参)`，挂在其后的那条声明上。叠多个时自下而上应用，与 Python 同序。
- **宏是普通函数**：标 `@macro`，签名是 `(Tokens) -> Tokens`。没有单独的宏 crate，没有 dylib，也没有 ABI 版本——编译器自带的 VM 直接跑它（[77](77-bytecode-vm.md) 是前提，这是那条路线的第一个真实用处）。
- **token 是封闭的四变体**：Group、Ident、Punct、Literal。要看结构时用编译器自己的解析器，把 token 解析成通用树（kind 加 children 加 span），不是语言里可求值的构造子——所以没有同像性，也不引入第二层「表示代码的值」。
- **展开是工作表，不是不动点**：每个宏调用跑一次，产物重新入队；嵌套深度与燃料都有上限，超限是编译错误。展开全部完成后，名字解析与类型检查各跑一遍。
- **沙箱**：编译期执行没有 IO、没有时钟、没有随机数，燃料按指令数计。违反即编译失败，构建因此可复现。
- **与内建标签分工**：`@export`、`@test`、`@deprecated`、`@target` 仍是编译器内建、名字保留；其余名字落到用户宏，同名冲突是编译错误。
- **没有表达式位的宏**。装饰器只能修饰声明；内联 DSL 只能吃字符串参数、走普通函数，编译期语法检查因此没有了。要加回来就是一条文法规则加一条主表达式分支，代价是第二个入口。

```
@macro
def derive_show(item: Tokens): Tokens = { ... }

@derive(Show)                  // 用户宏：吃被装饰声明，吐新声明
struct Circle { radius: Float }

@route("/circles")
@cached(ttl_seconds: 60)       // 可叠：自下而上应用，先 cached 再 route
def list(): Json = { ... }
```

**代价**：

- **编译时间变成「展开后近线性」**。展开产物的大小是数据相关的，[57](57-linear-compile.md) 的线性只对类型检查那一段成立，对整次构建不成立。
- **语法成为公开接口**。宏按 token 与 kind 名字工作，语法一改就是一次破坏性变更；这与换表面（[75](75-rust-surface-syntax.md) / [81](81-scala-surface.md)）的成本叠加在一起。
- **宏作者能造出语法合法、语义可疑的东西**。可读性责任从编译器转到库；一个库的 DSL 好不好读，语言管不了。
- **编译期跑任意代码**。即便有燃料与能力限制，构建时间仍可能被一个坏宏拖长；报错位置在宏内部，比手写代码难定位。
- **两套展开层次要分清**：宏在语法层，产物再走 [59](59-single-expansion-target.md) 的单一展开目标。这是两层，不是两个目标；混起来写规则就会乘法增长。
